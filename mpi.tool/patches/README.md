# patches - MPI implementation patches

Part of the mpi.tool.

## What it does

Source patches applied to supported open-source MPI implementations so that `tractor` can hook into and trace their internals (e.g. collective algorithms) where public MPI/PMPI interfaces aren't sufficient.

## Layout

Each implementation has two to four independent patches (disjoint file sets; apply with `patch -p1` from the top of the source tree, in any order):

- `<name>.patch` - hooks for trace collection (libmpi side: request/communicator helpers `mpi_internal_*`, `MPIC_*` as weak aliases of `PMPIC_*`, scheduler hooks; for MVAPICH2 2.3.x also the psm_queue.c / error_handling.c fixes).
- `<name>.fortran.patch` - Fortran bindings (libmpifort side). The Fortran wrappers call `PMPI_*` by default; when the redirect variable below is set (to anything other than `""` or `"0"`) they call the C `MPI_*` entry points instead, so a collector that wraps only the C layer (tractor) also sees Fortran calls (mpif.h, `use mpi` and `use mpi_f08`), exactly once per Fortran call. For MPICH 4.x/5.x and MVAPICH 4.x the `use mpi_f08` interfaces without buffer arguments are re-bound to generated shims in `wrappers_c/f08_redirect.c`, and `maint/local_python/binding_f08.py` is changed accordingly so an `autogen.sh` run produces the same binding; for MVAPICH2 2.3.x and MPICH 3.4.3 (no `binding_f08.py`) the `mpi_c_interface_nobuf.f90` is patched directly; for MPICH 3.4.3 `wrappers_c/cdesc.h` and `wrappers_c/Makefile.mk` are generated, so `wrappers_c/buildiface` is patched too and `autogen.sh` reproduces them.
- `<name>.shm.patch` - provider-selection fix only (MVAPICH 4.1 only): `pick_provider_from_list()` in `src/mpid/ch4/netmod/ofi/init_provider.c` starts from `best_score = -1` while `provider_preference()` gives `shm`/`sm2` -10, so they could never be picked, not even when forced with `FI_PROVIDER=shm`. The patch starts from `INT_MIN` as MPICH does; automatic selection still prefers every other provider.
- `<name>.misc.patch` - stock fixes only (MVAPICH2), none of them trace collection: (1) `src/mpid/ch3/channels/common/src/affinity/hwloc_bind.c`: `mv2_generate_implicit_cpu_mapping()` appends the CPU mapping with `snprintf(mapping+j, _POSIX2_LINE_MAX, ...)`, passing the whole buffer size instead of the space left; with `_FORTIFY_SOURCE` (Ubuntu's default at -O2) glibc aborts in `MPI_Init` ("buffer overflow detected") - the patch passes `sizeof(mapping) - j` (2.3.5, 2.3.7-1); (2) `src/mpid/ch3/channels/psm/src/psm_queue.c`: `psm_pe_yield()` releases/takes the global mutex only when it exists (`MPICH_THREAD_LEVEL == MPI_THREAD_MULTIPLE`), so a PSM build without `--enable-threads=multiple` compiles (2.3.5, 2.3.7-1); (3) `src/mpid/ch3/channels/common/src/util/error_handling.c` prints the signal name with `strsignal(sig)` instead of `sys_siglist[sig]`, which glibc 2.32+ no longer provides (2.3.5 only; 2.3.7-1 already uses `strsignal`).

The hook patches report library-internal communicators to the tool through `mpi_internal_comm_create(comm, kind)` / `mpi_internal_comm_free(comm)` (weak aliases of `pmpi_internal_comm_*`). Every committed communicator is reported once its rank mapping is usable (an intercommunicator's `local_comm` included); node, node-roots and ch4 leader communicators are reported where they are created. The free hook fires for the internal ones only: sub-communicators (`SUBCOMM` context-id field) and local communicators (`IS_LOCALCOMM`). The former `parent_comm` back-tracing (`mpi_internal_comm_translate_rank` & co., `*_table_rev`) has been removed.
